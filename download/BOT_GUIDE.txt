  1) ما هو هذا البوت؟ (شرح بسيط جداً)
═══════════════════════════════════════════════════════════════════════════

تخيل أن Pump.fun هو "سوق الأسهم" لتوكنات الميم على شبكة Solana. كل دقيقة
تطلق عشرات التوكنات الجديدة. بعضها يرتفع 100x في ساعات، وبعضها يموت خلال
دقائق (rug pull). البشر لا يستطيعون متابعة كل هذا يدوياً، فيأتي البوت ليكون
"عينك السريعة" + "محفظتك الذكية".

البوت يقوم بثلاثة أشياء رئيسية:

  ┌──────────────────────────────────────────────────────────────────┐
  │  1. يراقب كل التوكنات الجديدة على Pump.fun لحظة بلحظة             │
  │  2. يقرر أيها يشتري (أمام 84% من التوكنات تخسر)                    │
  │  3. يبيع تلقائياً في الوقت المناسب (ربح أو خسارة محدودة)          │
  └──────────────────────────────────────────────────────────────────┘

البوت يعمل على Railway (خدمة استضافة سحابية) 24/7. أنت لا تحتاج أن تشغّل
شيئاً على حاسوبك — فقط ادفع التغييرات إلى GitHub (git push) وسيقوم Railway
بنشرها تلقائياً.


═══════════════════════════════════════════════════════════════════════════
  2) كيف يربح؟ (نظرة عامة على الاستراتيجية)
═══════════════════════════════════════════════════════════════════════════

استراتيجية V549 (المفعّلة الآن) هي مقامرة عالية المخاطرة:

  ┌──────────────────────────────────────────────────────────────────┐
  │  فكرتها: ابحث عن "moonshot" — التوكن الذي سيرتفع 5x إلى 50x.    │
  │  عند وجوده، اراهن بكل ما تملك (ALL IN).                          │
  │  امسكه حتى يصل إلى القمة، ثم اخرج مع الربح.                      │
  └──────────────────────────────────────────────────────────────────┘

لماذا ALL IN؟ لأن الـ moonshots نادرة (0.5% من التوكنات). لو راهنت بـ 2%
فقط، حتى لو التقطت moonshot بـ 25x، الربح سيكون $10 على $20. لكن لو راهنت
بـ 100%، الربح سيكون $500. هذا هو السبب الوحيد لاختيار ALL IN.

العيب: 88-98% من الأشهر ستنتهي بخسارة كاملة للـ $20 (لأن الـ rug/fail_day1
يحدث قبل أن يتفعل SL). لكن 2-10% من الأشهر ستعطي ربحاً $27-$34 (170%).

النتيجة المتوقعة (متحوسط): سالبة (-$17 إلى -$28 شهرياً) لأن الـ moonshots
نادرة جداً. هذا ليس استثماراً، بل مقامرة عالية التقلب.

═══════════════════════════════════════════════════════════════════════════
  4) الاستراتيجية الموحدة V549 (تفصيل كل رقم)
═══════════════════════════════════════════════════════════════════════════

ملف الكود: backend/app/modules/trading_strategy/unified.py

الاستراتيجية مقسّمة إلى 3 أجزاء: الدخول، الخروج، الدفاع.

───────────────────────────────────────────────────────────────────────────
  أ) بوابات الدخول (متى نشتري؟)
───────────────────────────────────────────────────────────────────────────

  التوكن يجب أن يجتاز كل هذه الشروط قبل الشراء:

  ┌──────────────────────────────────────────────────────────────────────────┐
  │  الشرط                    │  القيمة   │  لماذا؟                        │
  ├──────────────────────────────────────────────────────────────────────────┤
  │  liquidity (السيولة)      │  ≥ $5,000  │  حتى نقدر نبيع لاحقاً          │
  │  chg_5m (تغير 5 دقائق)    │  8% ≤ x ≤ 60%  │  بدأ pump فعلي              │
  │  age (عمر التوكن)         │  30s ≤ x ≤ 180s  │  مبكر — قبل الذروة        │
  │  buys (عمليات شراء 24h)   │  ≥ 20     │  يوجد اهتمام فعلي             │
  │  buy/sell ratio           │  ≥ 1.3    │  المشترون > البائعون           │
  │  top-10 holders           │  ≤ 30%    │  لا أحد يملك نصيب يمكنه rug  │
  └──────────────────────────────────────────────────────────────────────────┘

  ملاحظة: لو أي شرط غير متوفر (لا يوجد بيانات)، لا يُحجب الدخول. هذا متعمّد
  لأن Pump.fun API لا يعطي كل البيانات دائماً.

───────────────────────────────────────────────────────────────────────────
  ب) سلم الخروج (متى نبيع؟)
───────────────────────────────────────────────────────────────────────────

  عند كل تحديث سعر، يفحص البوت القواعد بالترتيب التالي (الرقم 1 له أولوية):

  ┌─────────────────────────────────────────────────────────────────────────┐
  │ 1. sudden_dump  │  الذروة ≥ +15% والسعر هبط ≥ 25% من الذروة           │
  │                 │  → بيع فوري (انقلاب خطير)                            │
  ├─────────────────┼─────────────────────────────────────────────────────────┤
  │ 2. stop_loss    │  السعر ≤ سعر الدخول × 0.95 (-5%)                     │
  │                 │  → بيع فوري (قص الخسارة)                              │
  ├─────────────────┼─────────────────────────────────────────────────────────┤
  │ 3. mega_tp      │  السعر ≥ سعر الدخول × 11 (+1000% = 10x)              │
  │                 │  → بيع كامل (لا تزيد بعد)                            │
  ├─────────────────┼─────────────────────────────────────────────────────────┤
  │ 4. quick_tp     │  الذروة في [+15%, +50%) → بيع كامل                   │
  │                 │  (ربح معقول، اخرج بأمان)                             │
  ├─────────────────┼─────────────────────────────────────────────────────────┤
  │ 5. smart_trail  │  الذروة ≥ +50% → انتظر حتى يهبط:                      │
  │   (runner)      │  - إذا الذروة < +100%: هبوط 15% من الذروة            │
  │                 │  - إذا الذروة ≥ +100%: هبوط 10% من الذروة            │
  │                 │  (trail واسع لترك moonshots تكتمل)                    │
  ├─────────────────┼─────────────────────────────────────────────────────────┤
  │ 6. stagnation   │  بعد 4 ساعات + الذروة < +5% → بيع                   │
  │                 │  (التوكن ميت، لا فائدة من الانتظار)                   │
  ├─────────────────┼─────────────────────────────────────────────────────────┤
  │ 7. time_exit    │  بعد 5 أيام (7200 دقيقة) → بيع                       │
  │                 │  (حد أقصى للانتظار)                                   │
  └─────────────────┴─────────────────────────────────────────────────────────┘

───────────────────────────────────────────────────────────────────────────
  ج) الدفاع (حماية رأس المال)
───────────────────────────────────────────────────────────────────────────

  في V549، الدفاع شبه معطّل عمداً (لأن المستخدم طلب أقصى ربح مطلق):

  ┌─────────────────────────────────────────────────────────────────────────┐
  │ max_buys_per_day    = 10  (بلا حد عملي — 10 صفقات يومياً)              │
  │ daily_loss_stop_pct = 50% (لا يتوقف إلا إذا خسر نصف رأس المال في يوم)  │
  │ dd_half_pct         = 5%  (لا يتوقف إلا إذا تبقّى 5% من القمة — شبه معطل)│
  │ streak pause        معطل (نافذة 50 صفقة + شرط 5% WR — مستحيل التفعيل) │
  └─────────────────────────────────────────────────────────────────────────┘

  هذا يعني: البوت يستمر في المراهنة مهما خسر. لو رأس المال انخفض من $20 إلى
  $5، سيستمر في شراء توكنات جديدة (بحجم أصغر طبعاً لأن trade_pct يعمل
  على رأس المال الحالي).

───────────────────────────────────────────────────────────────────────────
  د) حجم الصفقة (trade_pct)
───────────────────────────────────────────────────────────────────────────

  trade_pct = 1.0 = 100% = ALL IN

  كل صفقة تستخدم 100% من رأس المال المتاح. لو كان لديك $20، الصفقة = $20.
  لو ربحت 10x → $200. لو خسرت → $0 (تنتهي اللعبة).

  max_concurrent_positions = 6 (يسمح بـ 6 صفقات مفتوحة في نفس الوقت، لكن
  عملياً ستكون الصفقة الأولى ALL IN فلا يبقى شيء للثانية).


═══════════════════════════════════════════════════════════════════════════
  5) رحلة التوكن الواحد (من الإطلاق حتى الخروج)
═══════════════════════════════════════════════════════════════════════════

  لنأخذ مثالاً واقعياً. توكن اسمه "PEPE2" أُطلق الساعة 12:00:00.

  ─────────────────────────────────────────────────────────────────────
  الساعة 12:00:30 (العمر = 30 ثانية):
  ─────────────────────────────────────────────────────────────────────
  • pumpfun_client يلتقط التوكن عبر WebSocket
  • البوت يفحص: liquidity=$8k ✓, chg_5m=12% ✓, age=30s ✓,
    buys=45 ✓, sells=20 → ratio=2.25 ✓, top10=18% ✓
  • كل البوابات اجتازت → البوت يفتح صفقة بـ $20 (ALL IN) عند سعر $0.001
  • trade registered في قاعدة البيانات (status=open, entry_price=$0.001)

  ─────────────────────────────────────────────────────────────────────
  الساعة 12:02:00 (بعد دقيقتين):
  ─────────────────────────────────────────────────────────────────────
  • السعر ارتفع إلى $0.0012 (+20%)
  • البوت يفحص: peak_gain=+20% (>= runner_threshold +50%؟ لا، +20% < +50%)
  • أيضاً: peak_gain >= quick_tp (+15%) → نعم → exit reason = "quick_tp"
  • البوت يبيع عند $0.0012 → ربح = $20 × 20% - 3% رسوم = +$3.40
  • رأس المال الجديد = $23.40

  ملاحظة: في V549، quick_tp=+15% يعني نبيع مبكراً. لو كان التوكن سيصبح
  moonshot، خسرنا الفرصة. لكن على المدى الطويل، هذه السياسة تلتقط معظم
  pump_dump (12% من التوكنات) قبل انقلابها.

  ─────────────────────────────────────────────────────────────────────
  مثال آخر — moonshot حقيقي:
  ─────────────────────────────────────────────────────────────────────
  • السعر ارتفع بسرعة: $0.001 → $0.005 (+400% في 5 دقائق)
  • peak_gain = +400% (>= runner_threshold +50%) → runner mode
  • trail_tighten_100 (لأن peak_gain ≥ 100%): trail_width × 0.40 = 25% × 0.40 = 10%
  • أي: يبيع فقط إذا هبط السعر 10% من الذروة
  • الذروة $0.010 (+900%)، السعر الحالي $0.009 (-10% من الذروة) → smart_trailing
  • البوت يبيع عند $0.009 → ربح = $20 × 800% - 3% = +$159
  • رأس المال الجديد = $179 (نمو 9x في صفقة واحدة)

  ─────────────────────────────────────────────────────────────────────
  مثال آخر — rug pull (السيناريو الشائع):
  ─────────────────────────────────────────────────────────────────────
  • السعر: $0.001 → $0.0005 (-50% في 10 ثوانٍ)
  • peak_gain = 0% (لم يربح أصلاً)
  • current_price = $0.0005 ≤ entry × 0.95 ($0.00095) → stop_loss fires
  • البوت يحاول البيع، لكن liquidity قد تكون اختفت
  • slippage إضافي: يبيع عند $0.0004 (خسارة 60%)
  • رأس المال الجديد = $8 (خسارة $12)


═══════════════════════════════════════════════════════════════════════════
  6) الحقيقة الرياضية (لماذا هذا أصعب مما تظن)
═══════════════════════════════════════════════════════════════════════════

  إحصائيات Pump.fun الحقيقية (من Cryptorank و Dune analytics، آخر 30 يوماً):

  ┌────────────────────────────────────────────────────────────────────┐
  │  نوع التوكن        النسبة   المصير                                │
  ├────────────────────────────────────────────────────────────────────┤
  │  fail_day1        69%     pump ثم موت خلال 6 ساعات                │
  │  rug pull         15%     liquidity تُسحب، -90% في ثوانٍ           │
  │  pump_dump        12%     pump +50-300% ثم ارتداد إلى -50%       │
  │  graduate         1.5%    صعود تدريجي +200-500% على مدى أيام     │
  │  moonshot         0.5%    5x إلى 50x على مدى 1-7 أيام             │
  └────────────────────────────────────────────────────────────────────┘

  → 84% من التوكنات تخسر. 16% فقط تربح. و 0.5% فقط moonshots.

  الرسوم الحقيقية (PumpPortal Lightning):
    - 1.0% رسوم بروتوكول على الشراء
    - 1.0% رسوم بروتوكول على البيع
    - 0.5% انزلاق سعري على الشراء (متوسط)
    - 0.5% انزلاق سعري على البيع (متوسط)
    - 1.5% انزلاق دخول (البوت يملأ بعد الـ pump بقليل)
    ─────────────────────────────────────
    المجموع: ~4.5% تكلفة لكل صفقة (ذهاباً وإياباً)

  التوقع الرياضي لكل صفقة V549:
    E[trade] = 0.69 × (-5%) + 0.15 × (-5%) + 0.12 × (-5%)   # losers (SL -5%)
             + 0.015 × (+150%) + 0.005 × (+800%)              # winners
             - 4.5%                                              # round-trip costs
             = -0.79% لكل صفقة

  → كل صفقة، في المتوسط، تخسر 0.79% من حجمها. لكن مع ALL IN، الـ variance
  عالية جداً. صفقة moonshot واحدة تعطي +800% وتمسح 100 صفقة خاسرة.

  11) الأسئلة الشائعة
═══════════════════════════════════════════════════════════════════════════

  س: هل البوت مربح الآن؟
  ج: لا. V549 مقامرة عالية التقلب. متوسط شهري = -$28 (خسارة). لكن 2-10%
     من الأشهر تعطي +$27 إلى +$34 (ربح كبير).

  س: لماذا ALL IN؟ أليس هذا جنوناً؟
  ج: نعم، جنون. لكن المستخدم طلب "أقصى ربح مطلق". لو راهنت بـ 2% فقط، حتى
     لو التقطت moonshot بـ 25x، الربح = $10. لو ALL IN، الربح = $500. الفرق
     هائل. لكن المخاطرة: ALL IN يعني خسارة كاملة عند أول rug.

  س: كم مرة يفتح البوت صفقات يومياً؟
  ج: في V549: حتى 10 صفقات يومياً، 6 متزامنة. عملياً: 2-8 صفقات/يوم.

  س: ماذا يحدث لو انقطاع الإنترنت أو إعادة تشغيل Railway؟
  ج: الصفقات المفتوحة تبقى في قاعدة البيانات. عند الإقلاع، البوت يقرأ
     الصفقات المفتوحة ويعيد فحصها. لكن لو الـ rug حدث أثناء الانقطاع،
     البوت قد يبيع متأخراً بخسارة كبيرة.

  س: كيف أغير الاستراتيجية لمحافظة؟
  ج: في unified.py، غيّر:
       trade_pct = 0.02       (2% حجم صفقة بدل 100%)
       stop_loss = 0.02        (SL ضيق -2%)
       max_buys_per_day = 1   (1 صفقة فقط يومياً)
     ثم git push. هذا يحوّل V549 إلى V544 (لا يخسر).

  س: ما الفرق بين paper_trading و live_trading؟
  ج: paper_trading يحاكي الصفقات دون مال حقيقي (افتراضي $20). live_trading
     يستخدم PumpPortal API لشراء فعلي بـ SOL. البوت مفعّل على paper افتراضياً.
     للتبديل إلى live: LIVE_TRADING_ENABLED=true في Railway.

  س: كيف أعرف أداء البوت؟
  ج: افتح الـ Dashboard (العنوان على Railway). سترى:
       • رصيد رأس المال الحالي
       • الصفقات المفتوحة (مع السعر الحالي والربح/الخسارة)
       • الصفقات المغلقة (آخر 50 صفقة)
       • إحصائيات (نسبة النجاح، متوسط الربح، إلخ)

  س: لو البوت خسر كل شيء، ماذا أفعل؟
  ج: الـ paper_capital_usd يبقى $20 في كل دورة (لا يُصفَّر فعلياً). لو
     خسرت كل شيء في live_trading، أودع SOL جديد في محفظتك وسيستأنف البوت.

  س: هل يوجد نسخة احتياطية؟
  ج: نعم — كل شيء في GitHub. git log يعرض كل الإصدارات. للرجوع إلى V544:
       git checkout 9d1ded7 -- backend/app/modules/trading_strategy/unified.py
       git commit -m "rollback to V544" && git push

  س: ما الذي يحتاجه البوت ليبدأ فعلاً بالربح؟
  ج: إضافة وحدة Raydium (لتداول التوكنات المتخرجة من Pump.fun برسوم 0.5%
     بدل 3%). هذا يحسّن التكاليف بـ 6x. لو أردت، أستطيع بناءها.
